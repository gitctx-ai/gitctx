## Objective

Enhance MCPFormatter to group search results by file in both YAML frontmatter and Markdown body. Uses filter_and_group_results() from base.py for shared filtering/grouping logic. Outputs YAML + Markdown format (LLM-optimized for MCP consumption).

**Architectural Decision**: YAML + Markdown is superior to JSON for MCP because:
- MCP protocol is format-agnostic (any text format allowed in `content[].text` field)
- YAML saves ~30% tokens vs JSON (no quotes/braces)
- Markdown code blocks provide syntax highlighting for LLMs
- More human-readable while remaining machine-parseable
- MCP spec emphasizes "format for LLM consumption" - YAML/Markdown excels here

**Before (current - no file grouping):**
```yaml

  - file_path: src/auth.py
    line_numbers: 42-58
    score: 0.820
    commit_sha: abc123
  - file_path: src/login.py
    line_numbers: 10-20
    score: 0.850
    commit_sha: def456
---

## src/auth.py:15-25
**Score:** 0.920 | **Commit:** abc123
```python
class AuthMiddleware:
    def __init__(self):
        self.config = load_config()
```

## src/auth.py:42-58
**Score:** 0.820 | **Commit:** abc123
```python
def process_request(self, request):
    return self.validate(request)
```
```

**After (with file grouping):**
```yaml
---
files:
  - file_path: src/auth.py
    language: python
    chunks: 2
    best_score: 0.920
  - file_path: src/login.py
    language: python
    chunks: 1
    best_score: 0.850
---

## src/auth.py (2 chunks)

**Lines 15-25** | **Score:** 0.920
```python
class AuthMiddleware:
    def __init__(self):
        self.config = load_config()
```

**Lines 42-58** | **Score:** 0.820
```python
def process_request(self, request):
    return self.validate(request)
```

## src/login.py (1 chunk)

**Lines 10-20** | **Score:** 0.850
```python
def authenticate_user(username, password):
    # Authentication logic
```
```

**Benefits:**
- Files listed once in YAML (not per-chunk)
- Chunk count per file visible at glance
- Best score per file for quick relevance assessment
- Markdown organized by file with clear section headers
- More LLM-friendly: reduced redundancy, clearer structure
