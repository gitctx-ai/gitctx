## Testing Philosophy

**What BDD Smoke Tests Should Verify:**
- ✅ Results are grouped by file (not how many chunks)
- ✅ Formats produce visually different output (not exact format strings)
- ✅ Filtering works (not exact threshold calculations)
- ✅ Complete workflow (index → search → format → output)

**What Unit Tests Should Verify (in later tasks):**
- Exact format strings (`:LINE_NUM  SCORE  PREVIEW`)
- Sorting algorithms (tie-breaking logic)
- Edge cases (empty content, singular/plural, etc.)
- Precise chunk counts and scores

**Why This Separation:**
- BDD with real indexing = slow but realistic
- Unit tests with mocks = fast and precise
- BDD catches integration issues, unit tests catch logic bugs
